# GreyNOC Detector Engine v0.9.0

Release date: 2026-05-18

## Release Position

v0.9.0 is the first release candidate for the GreyNOC Detector Engine as a
serious defensive threat-intelligence and detection-engine foundation.

This release establishes the core product direction:

- Defensive-only source ingestion.
- Evidence-gated detection validation.
- Explainable risk and exploitability scoring.
- Draft detection generation across common SOC backends.
- GreyNOC-exclusive Signal DNA and Detection Quality Passport intelligence.

## Highlights

### Evidence-Gated Detection Quality

Detections can be generated as drafts, but they cannot be promoted to validated
without passed validation evidence. Passed evidence must include reviewer,
telemetry source, and positive sample size.

### Detection Quality Passport

Each detection can receive a GreyNOC quality grade:

- Unproven
- Bronze
- Silver
- Gold
- Platinum

The grade is based on validation status, evidence, reviewer presence, telemetry
source, sample size, precision-ready test reports, true positives, and false
positives.

### GreyNOC Signal DNA

Threats can now receive a stable `gndna-*` fingerprint and signal-strength score
based on CVE/KEV context, source evidence, AI relevance, detection opportunities,
and SOC action density.

### Defensive Enrichment

EPSS enrichment is available through a local fixture path or the FIRST EPSS API
when live fetching is deliberately enabled.

### Detection Generation and Export

The engine can generate draft detections for:

- Sigma
- Splunk SPL
- Elastic KQL
- Microsoft Defender KQL
- YARA metadata-only
- Suricata metadata-only

Validated detection export bundles are available as JSON or readable text.

## Safety Guarantees

- The engine does not generate exploit code, malware, credential theft logic,
  persistence logic, unauthorized scanning, weaponized payloads, or bypass
  instructions.
- GitHub monitoring remains metadata-only.
- Public source content is treated as untrusted.
- Generated detections remain drafts until validation evidence supports
  promotion.

## Known Limits

- SQLite is the current local production backend; Postgres remains planned for
  multi-user deployments.
- Some new workflows are API-first and do not yet have CLI parity.
- Detection test reports are computed but not yet persisted as historical
  artifacts.
- CI logs were not visible through the current connector at release-prep time,
  so maintainers should verify GitHub Actions before publishing a GitHub Release.
